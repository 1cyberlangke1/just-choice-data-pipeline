# JEV 生态与开源复现调研

> 目的：① JEV 这个「决策模型」生态里有哪些开源复现、各自的数据形态；② 大家拿它干什么活；
> ③ 提炼他们可靠合成数据的做法，落到本管线的 workflow 设计上。
> 抓取日期：2026-09-25。配套阅读：`docs/可靠合成数据范式.md`（合成可靠性四档）。

## 1. JEV 是什么

一次前向、共享 `state`、多道**带类型**的问题（`choice` / `noul` / `score`），
直接读出概率分布，**不生成文本**。官方训练法叫 RLCD（Reinforcement Learning for Calibrated Decisions）。

四条性质决定了它需要什么样的训练数据：

1. 答案是**选项上的概率向量**，不是文本；
2. 选项是**运行时给的**，模型没有固定分类头 → 训练行必须自带选项列表；
3. 问题之间**互相不可见**，只共享 state → 一次请求可以装很多道无关的题；
4. 选项顺序会影响答案（listwise 交互）→ 必须有乱序增强，并单独测顺序敏感性。

## 2. 大家拿 JEV 干什么

### 2.1 官方用例地图

`docs.typesafe.ai/concepts/use-case-map` 把决策形状归纳成十类：
分类、检测、打分、路由、检索（语义找）、取回（给下游喂上下文）、排序、验证、ML 特征抽取、结构化字段抽取。

行业侧：AI 自动化软件、实时应用、大数据 map-reduce、通用验证（验证别人的 prompt / 推理链 / 工具调用）、
harness engineering（模型路由、上下文取回、错误检测）。具体场景列举很杂：RAG 重排、系统综述的文献筛选、
访谈转录打标、引文是否支持论断、模型路由、LLM 护栏、语义 lint、招聘简历评估、电商 listing 归一化、
内容审核、广告品牌安全、游戏客服、风控、需求预测、知识图谱补全。

### 2.2 有公开数字的生产落地

| 谁 | 干了什么 | 数字 |
|---|---|---|
| Vega（安全告警分诊） | 把 JEV 当**闸门**放在 LLM agent 前面，先廉价筛掉一批 | 忙租户关掉 15%、闲租户三分之一，三个 LLM 判官核对约 98% 正确；作者明说「JEV 不能替代判断」 |
| 浏览器自动化（`jev-ultrafast`） | 页面转成「编号控件列表」，JEV 只负责选哪个控件 | 一次航班搜索：17 次 JEV + 2 次文本生成，约 7 秒 / $0.004 |
| 游戏循环 | Doom 用结构化血量/敌人/出口，JEV 每 tick 选一个动作 | 约 10 req/s，$7/小时 |
| 数据清洗（`jev-curate`） | 用 rubric 过滤预训练语料：循环推理、阿谀、stub 代码 | 三个 preset，纯筛选不重写 |
| 护栏 / 级联 | 一批 `noul` + 一个 `score`，按阈值路由 | 官方阈值：>0.9 自动执行，0.5~0.9 谨慎，<0.5 升级人工 |

官方口径：70~500 ms 一次、$0.042 / MTok 输入、输出免费。一句话——**凡是有界答案空间、量大、
没人读它的文字**的地方。

### 3.1 它们的训练行长什么样

统一形状 = **一次 `/v1/systemone` 请求 + 每题一个 label**。
kev 用 `api.to_record()` 渲染，any2jev 直接写「what the model trains on is what the server feeds it」
——**训练行与推理请求逐字节同构**。这一条我们已经天然满足（同一份 contract）。

- 硬标签：`choice` 存选项名、`noul` 存布尔、`score` 存 0 起下标；
- 软标签：证据被故意抽掉的题给 `{"true": 0.5, "false": 0.5}`，教「没证据就别自信」；
- `jevlike` 最小格式：`{"context": "...", "options": [...], "label": 0}`。

## 4. 他们怎么可靠地合成数据

### 4.1 kev 的四来源优先级（官方 data-generation 文档）

1. **已有真实标注**——转换即可。少（<200 条）就只当尺子；多（1000+）就根本不用合成。
2. **LLM 按 spec 生成**——spec 三件套：`guidance`（细心的人会用的规则，含歧义怎么裁）、
   `variety`（要铺开的轴：语气/长度/语言/是否含单号日期/多议题）、`state_example`。
3. **人（或 agent）手写**——约 100 条以内可行。
4. **程序生成**——标签由规则算出，能产出**完全一致的标签**与**最小对**。

四条纪律（比技术细节重要）：

- **真实行永不进 train**，只进 calibration / development；
- 与真实行 state 相同的合成行直接丢掉（防泄漏）；切分按 **state 哈希**分组；
- 生成器**按目标分布反着要标签**：每批先算好各选项该出现几次，再让模型写，保证均衡；
- `errors.jsonl` 回流成 spec 里的一句 `guidance`——**每一条反复出现的错误，等于缺了一句规则**；
  定向爬山时把 `domain`/`variety` 收窄到失败模式，再补 200 条。

### 4.2 kev 的程序生成：contrastive policy（最值得抄的一个）

`hard-v1` 的 `long_policy` 家族：先随机生成一份 800~5000 token 的保险条款
（编号章节、定义、限额、子限额、免赔额、等待期、通知条件、**除外条款及其例外**、通用条款），
再生成一个理赔事实，标签由一个小规则引擎 `solve(facts)` 算出。

两条硬约束：

1. 只保留**引擎同意**的记录（生成器先挑目标结论，再构造能推出它的理赔事实）；
2. 只保留**恰好只有一条拒赔理由成立**的记录——否则就有优先级歧义，标签不再唯一。

干扰项是**故意造进去的**：条件成立但例外也成立的除外、差一点没到阈值的除外、
物品不属于该类的子限额、与本案无关的章节。切分时留出**没见过的规则结构**当 OOD。

### 4.3 增强：同一标签，多种外壳

| 增强 | 干什么 |
|---|---|
| 选项乱序 | 测顺序鲁棒性；kev 报 option-order flip rate（0.00~0.08） |
| 插「以上都不是」+ **none 最小对** | 同 state 一条有匹配选项、一条没有，教「没有正确答案时别硬选」 |
| 插无关干扰项 | 教「干扰项不影响已有选项的相对判断」 |
| `criteria` 描述三态 | 约 30% 为 `null`、60% 字符串、10% 结构化，覆盖「选项有/无描述」 |
| state / instructions 随机包装 | 同一事实换措辞、换长度、换语言 |
| 最小对 | 同 state 改一个事实，标签翻转——直接教「这个决策到底依赖什么」 |

### 4.4 切分与评测

- 切分单位是 **state 哈希**（同组不跨切分）；真实/合成分离；来源分离（trainable vs transfer）；
- 留出维度里最有价值的是**留出规则结构**，不是「更大的数字」；
- 指标：accuracy / Brier / ECE / AURC / coverage@error / 顺序翻转率 / **最小对两个兄弟都对的比例**。

## 5. 对本管线的结论

1. 「**标签先行 + 规则引擎算答案**」是主力范式，而且**完全不需要 LLM**；
2. 文本外壳才是 LLM 该干的活，且必须**可反解**（反解不出来就不猜）；
3. 选项乱序、none 最小对、`criteria` 描述三态，是三个低成本高收益的增强；
4. 真实/合成严格分离、按 state 哈希切分、留出规则结构——我们目前**一条都没做**；
5. 训练行与推理请求同构——我们已经满足（同一份 contract，直接导出即可）。
